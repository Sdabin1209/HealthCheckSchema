# 구조적 제약과 운영 정책

공통 Schema는 정보를 구분하는 데 필요한 제약을 정의한다. 필수 필드·허용 코드·서로 배타적인 분기, 의미상 비어 있으면 안 되는 문자열과 목록, 음수가 될 수 없는 개수·인덱스·버전, 양수 정책 한도, 범위를 표현하는 두 원소 배열 등이 해당한다. 구체적인 허용 조건은 각 Schema 원본이 정한다.

문항별 선택지·단위·범위·위험 기준은 QuestionBank 데이터다. 값이 공통 Schema를 통과하는 것과 해당 문항에서 유효한 것은 다른 판정이다.

요청 크기·발화 길이·응답 길이·이력 수·보관 기간 등의 운영 상한은 공통 wire 계약에서 강제하지 않는다. 입력 처리·저장·보관을 담당하는 서비스가 합의한 정책으로 적용한다. 제한이 없는 공통 Schema의 통과를 무제한 처리 용량 보장으로 해석하지 않는다.

식별자는 문자열이며 계약별 비어 있음 허용 여부를 따른다. 실제 대상의 존재, 턴 ID 유일성, 식별자 생성은 담당 컴포넌트의 책임이다. 요구자료의 `Q3b.빈도` 같은 축약은 예시의 표기법이며 실제 전달에서는 대상의 구조화된 필드를 사용한다.

허용 범위는 Schema 원본과 해당 필드의 의미·필요 이유를 함께 확인한다.
