# 계약 버전과 기록 기준

현재 계약 버전의 유일한 기준값은 `work/contracts/manifest.yaml`의 `version`이다. 값은 양의 정수로 관리한다. Svelte·패키지·문항 정의·테스트 자료 작성 형식의 버전은 각각 다른 대상이며 계약 버전 변경과 함께 올리지 않는다.

## 버전을 올리는 경우

현행 계약의 허용 구조, 필수 여부, 타입·제약, 필드의 의미 또는 생산·소비 책임 등 구현의 계약 준수에 영향을 주는 변경에 맞춰 manifest의 계약 버전을 올린다. 증가량은 1로 관리한다. 설명의 오타, 내용 변화 없는 문장 정리, 웹 배치·스타일, 동일한 계약을 사용하는 테스트 데이터 추가만으로는 올리지 않는다. 초안만 수정하고 현행 계약을 바꾸지 않은 경우에도 현행 계약 버전을 올리지 않는다.

계약 변경 시 원본·의미·필요한 예시를 함께 고치고 버전 기준값을 갱신한 뒤 `python3 verify.py`로 검증과 생성물을 갱신한다. 웹을 전달할 때는 `presentation/README.md`의 데이터 생성·빌드 절차도 수행한다. 다른 파일의 버전 숫자를 찾아 임의로 일괄 치환하지 않는다.

## 현재 생성물과 정적 예시

`generated/source_manifest.json`에는 생성 당시 기준 버전과 원본 해시가 들어간다. 웹의 버전 표시는 원본에서 생성한 데이터의 버전을 사용한다. 현재 안내 문서에는 현재 버전 번호를 중복 기입하지 않고 manifest 또는 생성 기준 정보를 참조한다.

현재 계약의 TurnTrace 정적 예시는 `work/testcases/schema_example_templates/TurnTrace.json`에서 생성한다. 템플릿의 version_fields 위치만 manifest의 계약 버전으로 치환하여 `work/testcases/schema_examples/TurnTrace.json`을 만든다. 생성된 JSON에는 실제 정수 버전이 들어가므로 독립적으로 읽고 검증할 수 있다. 생성 예시를 직접 수정하지 않고 템플릿을 수정한다. 템플릿의 자리표시는 실제 입출력 계약의 데이터가 아니다.

## 실제 Trace와 과거 기록

실제 Trace의 `contract_version`에는 기록을 생성한 구현이 당시 적용한 계약 버전을 저장한다. 저장 후에는 현재 manifest 값이 바뀌어도 기록의 버전을 바꾸지 않는다. 기록을 읽는 시점의 현재 버전으로 덮어쓰거나 현재 예시 생성기를 실제 기록에 적용하지 않는다.

실제 기록의 버전은 생성 시 정해져 저장되는 고정 값이며 구현 소스에 영구 상수로 박아 넣으라는 뜻은 아니다. 배포·호출에 적용한 계약 버전을 기록 시점에 제공해야 한다. 문항 정의 버전·세션 상태 revision과도 다른 값이다.
